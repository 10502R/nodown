# A 담당 문서 초안

노션에 그대로 붙여넣을 수 있도록 작성한 초안이다.
기획서 양식의 3번·6번과 기능명세서 양식의 1번에 해당한다.

작성 범위: 거래 탐지, 가맹점 상태 확인, 사례 생성, 기본요건 규칙 엔진

# 기획서 3. 문제 정의 및 제안 배경

## 해결하고자 하는 문제

헬스장, 필라테스, 학원, 피부관리실처럼 장기간 이용을 전제로 결제하는 서비스는 이용 시작 시점에 카드 할부로 결제하는 경우가 많다. 그런데 가맹점이 갑자기 폐업하거나 서비스를 중단하면 소비자는 남은 할부금을 계속 납부하면서도 서비스를 이용하지 못하는 상황에 놓일 수 있다.

현재는 소비자가 직접 다음 내용을 확인해야 한다.

- 가맹점이 실제로 영업을 중단했는지 확인
- 자신의 거래가 장기할부 거래에 해당하는지 확인
- 남은 할부금이 있는지 확인
- 계약서와 환불 요청 내역 등 관련 자료 수집
- 카드사에 문의하고 필요한 서류를 준비

이 과정은 금융서비스에 익숙하지 않은 소비자에게 부담이 된다. 특히 폐업 직후에는 가맹점과 연락이 되지 않는 경우가 있어, 피해 사실을 확인하고 자료를 준비하는 사이에 대응이 늦어질 수 있다.

## 대상 고객과 채널

주요 대상은 다음과 같다.

- 장기 회원권이나 이용권을 카드 할부로 구매한 소비자
- 헬스장·필라테스·학원 등 장기간 이용 서비스의 결제 고객
- 가맹점 폐업 이후에도 남은 할부금을 납부하고 있는 고객

서비스는 카드사 내부 업무 화면에서 대상 거래를 선별하고, 카드사 앱 알림을 통해 소비자에게 안내하는 구조를 기본으로 한다. 공모전 MVP에서는 카드사 앱을 별도로 만들지 않고 웹 화면으로 알림 과정을 시뮬레이션한다.

## 제안 배경

카드사는 거래금액, 할부기간, 가맹점 업종, 사업자 상태와 같은 정보를 이미 보유하거나 확인할 수 있다. 이 정보를 활용하면 소비자가 민원을 제기한 뒤에 대응하는 방식에서 벗어나, 피해 가능성이 있는 거래를 먼저 찾아 안내할 수 있다.

다만 가맹점 폐업만으로 소비자의 피해나 할부항변 인정 여부를 확정할 수는 없다. 이미 환불이 되었거나 다른 지점에서 서비스를 이용할 수 있는 경우도 있기 때문이다. 따라서 카드사는 먼저 확인이 필요한 거래를 선별하고, 소비자가 제출한 계약서·문자·이용 기록을 정리한 뒤 최종 심사를 진행하는 구조가 적절하다.

이번 MVP에서는 카드사 운영데이터 대신 합성 거래데이터를 사용한다. 거래 조건 필터링, 가맹점 상태 확인, 사례 생성, 기본요건 확인이 실제로 동작하는지 보여주는 데 초점을 둔다. 실제 개인정보와 실제 업체 정보는 사용하지 않는다.

## 제안으로 달라지는 점

기존에는 소비자가 피해를 인지하고 필요한 자료를 스스로 찾아야 했다. 제안 서비스에서는 다음 순서로 대응할 수 있다.

1. 카드사가 장기할부·잔여금 거래를 먼저 선별한다.
2. 가맹점 상태를 확인하고 폐업 거래를 별도 사례로 만든다.
3. 소비자에게 확인이 필요한 상황을 안내한다.
4. 소비자가 계약서와 환불 요청 자료를 입력한다.
5. 자료 분석 결과와 기본요건 확인 내용을 바탕으로 카드사 제출자료를 준비한다.

이를 통해 소비자는 자신의 거래가 왜 안내 대상이 되었는지 확인할 수 있고, 카드사는 반복적인 자료 확인 업무를 일정한 기준으로 시작할 수 있다.

# 기획서 6. 기대효과 및 확장 가능성

## 소비자 측 기대효과

- 가맹점 폐업 이후에도 남은 할부금과 이용 가능 여부를 빠르게 확인할 수 있다.
- 거래가 안내 대상이 된 이유를 금액·할부기간·잔여금·가맹점 상태별로 확인할 수 있다.
- 계약서, 환불 요청 문자, 서비스 중단 안내문 등 필요한 자료를 한 흐름에서 정리할 수 있다.
- 자료가 부족한 경우 무엇을 추가로 확인해야 하는지 알 수 있다.
- 서비스가 할부항변 인정 여부를 임의로 판단하지 않으므로, 소비자가 안내 결과를 최종 결정으로 오해할 가능성을 줄일 수 있다.

## 카드사 및 서비스 제공자 측 기대효과

- 민원이 접수된 이후에만 확인하던 구조에서 벗어나 피해 가능 거래를 선제적으로 확인할 수 있다.
- 거래 조건을 코드로 먼저 확인하므로 담당자마다 다른 기준으로 사례를 시작하는 문제를 줄일 수 있다.
- 소비자가 제출한 자료의 시간순 관계와 부족한 증빙을 정리해 심사 전 자료 확인에 활용할 수 있다.
- 가맹점 상태, 잔여 할부금, 서비스 중단 여부를 중심으로 초기 상담의 일관성을 높일 수 있다.
- 장기적으로는 소비자 보호 활동과 민원 대응 품질을 함께 관리할 수 있다.

## 확장 가능성

### 업종 확장

MVP는 헬스장 폐업 사례를 대표 시나리오로 사용하지만, 데이터의 업종 필드와 규칙을 분리해 두면 다음 업종에도 적용할 수 있다.

- 필라테스·요가·수영장
- 학원·교육 이용권
- 피부관리·미용 회원권
- 웨딩·행사 패키지
- 장기 렌탈·구독 서비스

업종별로 최소 결제금액이나 이용기간은 달라질 수 있으므로, 실제 서비스에서는 카드사 정책과 업종별 기준을 별도로 설정해야 한다.

### 기능 확장

- 카드사 앱 푸시와 문자 발송 연동
- 실제 사업자 상태조회 API 연동
- 카드사 거래내역과 잔여 할부금 자동 대조
- 소비자 입력 자료의 출처 관리 강화
- 카드사별 공식 접수 경로 안내
- 담당자용 사례 검색 및 처리 상태 관리

위 기능은 카드사 제휴와 보안심사, 개인정보 처리 기준을 확인한 뒤 단계적으로 적용할 수 있다.

### 금융 외 적용 가능성

계약이 먼저 체결되고 서비스가 장기간 제공되는 분야에서는 비슷한 자료 정리 구조를 활용할 수 있다. 예를 들어 구독서비스 해지·환불 분쟁, 장기 교육서비스 중단, 렌탈서비스 사업자 폐업과 같이 계약내용·결제내역·서비스 제공 여부를 함께 확인해야 하는 상황에 적용할 수 있다.

다만 금융서비스에서 사용하는 판정 기준을 다른 분야에 그대로 적용하지 않고, 각 분야의 계약조건과 소비자 보호 기준에 맞춰 별도 규칙을 마련해야 한다.

## 확장 시 지켜야 할 원칙

- AI 분석 결과를 법적 최종 판단으로 표현하지 않는다.
- 실제 개인정보는 필요한 최소 범위에서만 처리한다.
- 합성데이터와 실제 입력자료를 화면에서 구분한다.
- 규칙 엔진의 기준과 판정 근거를 확인할 수 있게 한다.
- 최종 인정 여부는 해당 금융기관 또는 담당 기관의 심사로 남겨둔다.

# 기능명세서 1. MVP 구현 범위

## 1-1. A 담당 MVP 구현 기능

### 합성 카드거래 목록

거래 ID, 가맹점명, 업종, 결제금액, 결제일, 할부기간, 납부 회차, 잔여 회차, 잔여 할부금, 사업자 식별값, 가맹점 상태를 JSON으로 관리한다.

현재 A 구현에서는 12건의 합성 거래를 사용한다. 금액과 조건을 일부러 다르게 설정해 필터 통과·제외·상태 추가 확인 사례를 함께 보여준다.

### 장기할부 피해 가능 거래 필터

다음 조건을 순서대로 확인한다.

- 결제금액 200,000원 이상
- 최초 할부기간 3개월 이상
- 잔여 할부금이 0원보다 큼
- 장기 서비스 업종

각 거래에는 조건별 충족 여부와 제외 사유를 함께 표시한다. 이 단계는 할부항변 인정 여부를 판단하는 단계가 아니라, 추가 확인이 필요한 거래를 선별하는 단계다.

### 가맹점 상태조회 모의 API

실제 공공 API를 호출하지 않고 합성 응답을 사용한다. 상태는 정상 영업, 휴업, 폐업, 확인 불가로 구분한다.

응답에는 사업자 식별값, 상태코드, 상태명, 폐업일, 합성 응답 여부를 포함한다.

### 사례 생성 API

필터 조건을 통과하고 가맹점 상태가 폐업인 거래만 사례로 생성한다.

요청:

    POST /api/cases
    {"transactionId": "TX-1003"}

응답:

    {
      "caseId": "CASE-001",
      "caseUrl": "/detection/CASE-001",
      "isSynthetic": true
    }

정상 영업 거래나 기준 미달 거래는 사례를 생성하지 않고 제외 사유를 반환한다.

### 기본요건 규칙 엔진

규칙 엔진은 확률이나 위험점수를 만들지 않는다. 다음 조건을 확인하고 조건별 상태를 화면에 표시한다.

- 가맹점 폐업 여부
- 남은 할부금 존재 여부
- 서비스 중단 후 미이용 여부
- 결제금액 및 할부기간 기준
- 환불 미완료 여부
- 대체 서비스 미제공 여부
- 소비자 귀책 없음
- 증빙자료 확보 여부

판정 결과는 다음 세 가지 중 하나다.

- 기본요건 충족 가능성 있음
- 추가자료 확인 필요
- 기본요건 충족 어려움

자료가 확인되지 않는 조건은 임의로 충족 처리하지 않고 추가자료 확인 필요로 표시한다. 최종 인정 여부는 카드사가 결정한다.

### 거래 탐지 화면

거래 목록, 필터 조건, 제외 사유, 가맹점 상태, 알림 대상 여부, 사례 생성 버튼을 표시한다. 화면 상단과 상태조회 결과에는 공모전 시연용 합성 데이터라는 점을 표시한다.

## 1-2. 이번 MVP에서 구현하지 않는 A 관련 기능

- 실제 카드사 거래 API 연결
- 실제 공공기관 사업자 상태조회 API 연결
- 실제 카드사 앱 푸시 또는 문자 발송
- 카드사 자동 접수
- 결제 자동 취소 또는 환불 확정
- 할부항변 인정 여부의 자동 최종 판단
- 실제 고객 개인정보 사용
- 장기간 거래·문서 보관

## 1-3. 다른 담당자 기능과의 경계

- 카드사 앱 알림 화면과 전체 페이지 연결은 D 담당이다.
- 계약서·문자 업로드와 OCR은 B 담당이다.
- 비정형 자료의 시간순 분석과 제출자료 문장 생성은 C 담당이다.
- A는 거래 사례 ID와 상태, 규칙 판정 결과를 다음 화면에서 사용할 수 있도록 전달한다.

# 합성데이터 제작 기준

## 제작 원칙

합성데이터는 실제 고객이나 실제 업체의 자료를 복사해 만든 것이 아니다. 최종 아이디어의 대표 사례와 필터 기준을 바탕으로 테스트 목적에 맞게 직접 구성했다.

1. 대표 사례를 먼저 정한다.
   - 올데이 피트니스
   - 2026년 3월 2일 결제
   - 1,200,000원
   - 12개월 할부
   - 남은 할부금 700,000원
   - 2026년 8월 10일 폐업
2. 대표 사례와 비교할 탈락 조건을 정한다.
   - 금액 기준 미달
   - 일시불
   - 장기 서비스 업종 아님
   - 잔여 할부금 없음
   - 정상 영업
   - 휴업 또는 상태 확인 불가
3. 각 거래에 예상 결과를 붙인다.
4. 사업자 식별값과 카드 끝 네 자리는 가상값으로 정한다.
5. 같은 입력에는 같은 결과가 나오도록 규칙을 코드로 고정한다.

| TX-1010 | 정상 영업 | 학원, 500,000원, 잔여금 있음 | 알림 제외 |
| TX-1011 | 잔여금 없음 | 요가, 500,000원, 3개월 완납 | 제외 |
| TX-1012 | 상태 확인 불가 | 피트니스, 1,000,000원, 상태 미확인 | 상태 추가 확인 |

이 데이터는 거래 필터가 정상적으로 작동하는지 확인하기 위한 것이며, 실제 소비자의 피해나 할부항변 성립을 의미하지 않는다.

위 12건은 A 담당의 거래 탐지·가맹점 상태 분기를 검증하기 위한 데이터다. 최종 아이디어에서 말한 ‘가능성 높음·추가 확인·판정 어려움·자료 모순’ 각 3건은 B의 증빙 자료와 C의 분석 입력이 붙는 단계에서 별도 조합한다. 거래 조건과 제출 자료를 한 데이터에 억지로 섞지 않고 담당 범위에 맞춰 나누었다.
